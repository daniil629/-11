# Запуск Message Keeper на Botkeep

Эта инструкция предназначена для бесплатного тарифа Botkeep и проекта Message Keeper v1.2.0.

## Что понадобится

- Аккаунт Botkeep с подтверждённой почтой: https://botkeep.cloud/app/create
- Репозиторий с исходным кодом без `.env` и `data/`.
- Токен бота из локального `.env`, полученный у @BotFather. Его нужно вставить только в разделе Environment / Secrets хостинга.
- Для сохранения старого архива — отдельная резервная копия `data/`. В публичный репозиторий её не загружать.

## Параметры приложения

| Поле | Значение |
|---|---|
| Source | GitHub или ZIP |
| Repository | `https://github.com/daniil629/saveMOD` |
| Branch | `main` |
| Project root | Корень репозитория, где находится `requirements.txt` |
| Runtime | Python 3.12; если недоступен — Python 3.11 |
| Start command | `python -m app.main` |
| RAM | 512 MB |
| CPU | 50% |
| Storage | 1 GB |
| Public port / domain | Не требуется: используется Telegram long polling |

При загрузке ZIP используйте архив, в котором `requirements.txt` находится в корне, без дополнительной внешней папки.

## Environment / Secrets

`BOT_TOKEN` обязательно добавить как секрет. Остальные значения можно добавить как обычные переменные окружения.

| Переменная | Значение для бесплатного тарифа |
|---|---|
| `BOT_TOKEN` | Настоящий токен из @BotFather — только в Secrets |
| `DATA_DIR` | `./data` |
| `SAVE_MEDIA` | `true` |
| `MAX_MEDIA_SIZE_MB` | `10` |
| `RETENTION_DAYS` | `3` |
| `CLEANUP_INTERVAL_HOURS` | `6` |
| `LOG_DELETIONS` | `true` |
| `LOG_EDITS` | `true` |
| `SAVE_MEDIA_ON_REPLY` | `true` |
| `LOG_LEVEL` | `INFO` |

Ограничения выбраны потому, что на бесплатном тарифе всего 1 GB хранилища. Не отключайте автоочистку и не ставьте `RETENTION_DAYS=0`, иначе медиа могут заполнить диск.

## Порядок запуска

1. Остановите старый экземпляр бота на компьютере. Нельзя запускать два long polling-процесса с одним токеном одновременно.
2. Создайте приложение в Botkeep и укажите параметры из таблицы.
3. Добавьте переменные окружения и секрет `BOT_TOKEN`.
4. Выполните Deploy / Import, дождитесь установки зависимостей и нажмите Start.
5. Откройте Console. При успешном запуске должна появиться строка `Started as @...`.
6. Откройте бота в Telegram и отправьте `/start`, затем `/status`.
7. Проверьте редактирование и удаление нового тестового сообщения.

## Существующая база и медиа

Самый простой первый запуск — с новой чистой базой. Старая папка `data/` при этом остаётся на Google Диске как резервная копия.

Если нужно перенести старую историю:

1. Полностью остановите старый бот и дождитесь корректного закрытия SQLite.
2. Сделайте новую согласованную резервную копию `data/` после остановки. Не копируйте базу из работающего процесса.
3. Остановите приложение на Botkeep.
4. Загрузите `messages.db` и папку `media/` в `data/` на хостинге, сохранив структуру каталогов.
5. Файлы `messages.db-wal` и `messages.db-shm` из старой несогласованной копии отдельно не переносите.
6. Запустите приложение и проверьте `/status`.

Независимую копию важных данных храните вне хостинга. Бесплатный тариф не является гарантией сохранности данных.

## Если что-то не работает

- **401 Unauthorized:** токен неверный или отозван. Обновите секрет `BOT_TOKEN`.
- **409 Conflict:** ещё работает другой экземпляр с тем же токеном. Остановите его и перезапустите приложение.
- **No module named app:** команда запуска выполняется не из корня проекта. Проверьте Project root и команду `python -m app.main`.
- **Диск заполняется:** уменьшите `RETENTION_DAYS` до `1` и `MAX_MEDIA_SIZE_MB` до `5`, затем перезапустите приложение.
- **Бот не поддерживает Business:** включите Business / Secretary Mode в @BotFather.
