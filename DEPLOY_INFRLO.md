# Message Keeper на Infrlo

Готовая конфигурация для бесплатного тарифа Infrlo: **512 МБ RAM, 2 ГБ хранилища**. Бот по-прежнему использует Telegram long polling, SQLite и текущие функции v1.2. Публичный webhook не нужен.

Официальное описание тарифа: <https://github.com/infrlo/Infrlo>. Панель: <https://dash.infrlo.com/>.

## Что добавлено для Infrlo

- `build-infrlo.sh` — устанавливает зависимости без pip-кэша.
- `start-infrlo.sh` — переходит в корень проекта и запускает один процесс бота.
- `.python-version` — выбирает Python 3.12.
- `app/health.py` — лёгкие ответы `/`, `/health` и `/healthz`, если платформа передала `PORT`.
- Health-check работает **в том же процессе**, что и polling: второй бот не запускается.
- В ответе health-check есть только статус, имя сервиса и версия — нет токена, сообщений или статистики.

## 1. Обновите GitHub-репозиторий

Загрузите новые файлы проекта в существующий репозиторий:

```text
https://github.com/daniil629/saveMOD
```

В репозитории должны оказаться как минимум:

```text
app/health.py
app/main.py
app/config.py
build-infrlo.sh
start-infrlo.sh
.python-version
requirements.txt
DEPLOY_INFRLO.md
```

**Не загружайте** `.env`, `data/`, `messages.db`, `messages.db-wal`, `messages.db-shm`, медиа или токен. Они исключены через `.gitignore`.

## 2. Остановите старый polling-процесс

Перед запуском копии на Infrlo остановите локальный бот на Windows: в окне, где он запущен, нажмите `Ctrl+C` и дождитесь завершения.

Одновременно с одним токеном должен работать только **один** экземпляр long polling. Иначе Telegram вернёт `409 Conflict`.

Старые файлы в Google Drive не изменяйте — это резервная копия.

## 3. Войдите и создайте приложение

1. Откройте <https://dash.infrlo.com/>.
2. Нажмите **Continue with Google** и войдите в своём браузере. Пароль и токен никому не отправляйте.
3. Нажмите **Deploy** или **Deploy Now**.
4. Выберите **From Public URL**. Можно также выбрать **From GitHub Account**, если хотите подключить свой GitHub.
5. Заполните поля:

| Поле | Значение |
|---|---|
| **App Name** | `msgkeeper` |
| **Repository URL** | `https://github.com/daniil629/saveMOD` |
| **Branch** | `main` |

Имя приложения должно быть коротким, строчными буквами; `msgkeeper` соответствует ограничениям формы.

6. Нажмите **Next**.

## 4. Впишите команды

На шаге **Build Config** замените значения по умолчанию:

| Поле | Точное значение |
|---|---|
| **Build Command** | `sh build-infrlo.sh` |
| **Run Command** | `sh start-infrlo.sh` |

Скрипты сами переходят в каталог проекта. Build использует `python3 -m pip`, а Run — `python3 -m app.main`.

## 5. Добавьте Environment Variables

Нажмите **Add** для каждой строки и внесите ключ и значение:

| Key | Value |
|---|---|
| `BOT_TOKEN` | токен от @BotFather — вставьте его только в эту форму |
| `DATA_DIR` | `./data` |
| `SAVE_MEDIA` | `true` |
| `MAX_MEDIA_SIZE_MB` | `10` |
| `RETENTION_DAYS` | `3` |
| `CLEANUP_INTERVAL_HOURS` | `6` |
| `LOG_DELETIONS` | `true` |
| `LOG_EDITS` | `true` |
| `SAVE_MEDIA_ON_REPLY` | `true` |
| `LOG_LEVEL` | `INFO` |

Эти настройки ограничивают размер одного файла и регулярно очищают старые данные, сохраняя отчёты об удалениях/правках и работу с медиа.

### Нужно ли добавлять PORT?

**Сначала не добавляйте `PORT` вручную.** Если Infrlo сам передаёт его, бот автоматически поднимет health-check и в журнале появится:

```text
Health check listening on 0.0.0.0:<порт>
```

Если Infrlo явно потребует в логах слушать конкретный порт, добавьте `PORT` с **именно этим номером** и сделайте Redeploy. Не выбирайте номер наугад и не перезаписывайте уже выданный платформой `PORT`.

## 6. Запустите и проверьте

1. Нажмите **Deploy**.
2. Откройте приложение → **Logs**.
3. Дождитесь строки:

```text
Started as @<username> (id=<id>)
```

4. Если есть выданный Infrlo домен, откройте его. Должен появиться JSON примерно такого вида:

```json
{"status":"ok","service":"message-keeper","version":"1.2.0"}
```

5. В Telegram отправьте боту `/start`: должны открыться фиолетовое приветствие и кнопки помощи/поддержки.
6. Проверьте Business-функции: с другого разрешённого аккаунта отправьте сообщение, измените и удалите его. Должны прийти отчёты о правке и удалении.
7. Проверьте `/status`: счётчик сообщений должен увеличиться.

Если домен не отвечает, но в Logs есть `Started as ...` и Telegram-функции работают, polling сам по себе исправен; возможно, платформа не выдала HTTP-порт.

## 7. Проверьте сохранность данных

Публичные материалы Infrlo не дают достаточного подтверждения, что локальная файловая система сохраняется после **каждого** Redeploy. Поэтому не считайте `2 GB storage` автоматической гарантией постоянного SQLite.

### Безопасная проверка обычного перезапуска

1. После тестового сообщения запишите число сообщений из `/status`.
2. В панели нажмите **Stop**, затем **Start** — не **Redeploy**.
3. Снова откройте `/status`.

Если число и история остались, обычный перезапуск сохраняет файлы.

### Проверка Redeploy — только на тестовых данных

Не нажимайте Redeploy с ценной историей. Если хотите проверить пересборку, сначала используйте только тестовые сообщения, затем нажмите **Redeploy** и повторите `/status`.

- Если история осталась — файлы пережили эту пересборку.
- Если база пуста — локальный диск нельзя считать постоянным при Redeploy. До реального использования нужен постоянный volume/каталог от Infrlo либо внешняя БД и отдельное хранение медиа. Не загружайте старую рабочую базу в такой режим.

Если в настройках Infrlo появится постоянный volume, укажите его каталог в `DATA_DIR` вместо `./data`.

## Перенос старой базы — необязательно

Первый запуск с чистой базой безопаснее. Старые сообщения, удалённые до подключения, Telegram всё равно не восстановит.

Если позже понадобится перенос:

1. Остановите старый бот и дождитесь полного завершения процесса.
2. Сделайте согласованную резервную копию SQLite.
3. Не копируйте живые `messages.db`, `messages.db-wal` и `messages.db-shm` во время работы бота.
4. Загружайте резервную копию только через подтверждённый постоянный механизм хранения Infrlo.

## Диагностика

| Симптом | Что сделать |
|---|---|
| `409 Conflict` | Остановить локальный или другой hosted-экземпляр с тем же токеном. Оставить один polling-процесс. |
| `401 Unauthorized` | Проверить `BOT_TOKEN` в Environment Variables; при необходимости перевыпустить токен через BotFather. |
| `python3: not found` | Заменить команды на `python -m pip install --no-cache-dir -r requirements.txt` и `python -m app.main`, затем сообщить о различии окружения. |
| `No module named ...` | Проверить, что Build Command завершился без ошибки и репозиторий содержит обновлённый `requirements.txt`. |
| Нет отчётов | Проверить Business/Secretary Mode в BotFather и разрешённые чаты в Telegram. |
| Данные исчезли после Redeploy | Считать файловую систему непостоянной; не хранить там единственную копию архива. |

Не публикуйте токен в Logs, GitHub, Telegram или переписке с поддержкой.
